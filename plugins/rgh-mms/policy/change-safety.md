# Change Safety Policy

Rules for load-bearing changes made by coding agents.

## Contract-first (when enabled)

When `.agentic/harness.yaml` enables `contracts` or the product profile requires
it:

1. Scaffold a change contract before load-bearing edits.
2. Record predicted fixes, risks, and settle criteria.
3. Settle with KEEP / IMPROVE / ROLLBACK and evidence after merge.

Pure docs and trivial refactors may skip contracts per product `local-policy.md`.

## Supervisor loops

Milestone and feature delivery use role separation:

- **Planner** — read-only plan
- **Implementor** — code, tests, docs, CI
- **Reviewer** — conventions and structure (not acceptance criteria)
- **Approver** — acceptance criteria with evidence

Supervisors stay thin: structured summaries only, no full diffs in supervisor
context. Every phase (plan, implement, review, approve) plus optional
Review-loop step-back `researcher` dispatches fresh (subagent when supported,
otherwise session) — see
[milestone-delivery](../workflows/milestone-delivery.md#supervisor-context-discipline).

## Default-branch merge gate

Merging into the repository **default branch** is always a human hard gate.
Manifest `delivery.agent_may_merge` never authorizes default-branch merges.

When `delivery.integration_mode` is `milestone-aggregate` (platforms without
stacked PRs), the supervisor may merge approved issue PRs into the **milestone
tracking branch** only. The human gate applies to the milestone aggregation PR
landing on the default branch in bulk. See
[milestone-delivery integration modes](../workflows/milestone-delivery.md#integration-modes).

## Round caps and escalation

- Review and approve loops cap at 5 rounds each.
- Plan-time acceptance-criteria defects (`acceptance_criteria_defects` from
  [planner](../roles/planner.md)) escalate at
  [milestone-delivery](../workflows/milestone-delivery.md) Loop step 4
  before implement — same routing as non-empty `blockers`; telemetry reuses
  `dependency_blocker`. After human rewrite/waiver, update the work item
  (remove/annotate waived criteria) and pass waived defect ids
  (`acceptance_criteria_defects[].id`) as Approver Input;
  [approver](../roles/approver.md) verifies adjudicated criteria and must
  not re-fail the same defect.
- On first bug-class circuit-breaker fire ("recurrence #2"), route to
  **circuit-breaker remediation**: optional **step-back** via fresh
  `researcher` first (when the structural fix is unclear or spans modules),
  then **structural-rewrite** `implementor`, per
  [milestone-delivery Review loop](../workflows/milestone-delivery.md) — not a
  normal findings batch. Do not escalate on first fire alone. Escalate before
  structural-rewrite when `researcher` `recommendation` is
  `"insufficient evidence"`.
- Escalate before the cap when remediation fails (implementor cannot complete
  the labeled rewrite, or `ci.local_command` exits non-zero after the rewrite
  attempt), the same bug class recurs after remediation (post-rewrite breaker
  fire), or repeated same-category failures continue after a remediation
  attempt. Cap exhausted → escalate (separate from before-cap cases; see the
  Review loop).
- Escalation messages go to the human owner with round counts and pattern.

## Generated files

Client adapter outputs from `scripts/generate-adapters.py` that go through
`with_provenance` carry a `Generated by rgh-mms` provenance comment (agents,
skills dogfood copies, cursor rules, `CLAUDE.md` (self-host only — see
[`mission-boundaries.md#no-automatic-onboarding-time-rewrites-of-hand-authored-instructions`](mission-boundaries.md#no-automatic-onboarding-time-rewrites-of-hand-authored-instructions)),
and copilot instructions). Do not hand-edit them — regenerate instead. The generator refuses to overwrite
or delete unmarked managed files without `--force`. The version stamp file
`.agentic/generated/.generate-version` is also managed by the generator but
is plain text (no provenance comment) and is exempt from that refuse gate so
VERSION bumps do not require `--force`. `--check` also ignores that gitignored
stamp (not a VCS-tracked adapter).

**Self-host exception:** when the target is this repository (or `--self-host`),
inputs come from `harnesses/self-host/`, not the product-input paths in
`harnesses/README.md` **Layout** / `plan_files` (e.g.
`harnesses/cursor/rules/`, `harnesses/claude-code/agents/` + `skills/`,
`harnesses/generic/copilot-instructions.md` else stub).

## Author integration checklist

Pre-PR obligations when changing `policy/`, `roles/`, or `workflows/`. This
documents existing obligations; it does not add new CI jobs or
[round caps](#round-caps-and-escalation). Split into shipped
machine-enforced, planned machine-enforced, and author-judgement.
List each rule once.

### Shipped machine-enforced

Run the named script; do not eyeball:

| Obligation | Enforcer |
|------------|----------|
| Relative Markdown links resolve under `roles/`, `workflows/`, `policy/`, `skills/` | `scripts/validate-policy-pack.py` (`md-links`; issue #33) |
| Role `Used by:` ↔ workflow symmetry | `scripts/validate-policy-pack.py` (`role-workflow-symmetry`; issue #33) |
| Profile policy files and capabilities | `scripts/validate-policy-pack.py` (`profile-policy`, `profile-capabilities`; issue #33) |
| Client adapters match `plan_files` inputs (product `harnesses/…` vs self-host `harnesses/self-host/…`; see `harnesses/README.md` Layout / Generation modes) | `scripts/generate-adapters.py --check` (issue #50) |

### Planned machine-enforced

None today. When a new obligation gains a script enforcer, add the row here
until the gate ships, then move it into **Shipped machine-enforced**.

### Author-judgement

No script covers these today. When an item becomes checkable, move it into
shipped machine-enforced under the owning script
(`scripts/validate-policy-pack.py` via #33, or
`scripts/generate-adapters.py --check` via #50) rather than duplicating it
here:

1. **Single source of truth.** Add each new topic to
   [`policy/INDEX.md`](INDEX.md); defer from consumers rather than restating.
2. **Workflow-order trace.** Trace every claimed gate to a documented step
   that runs before PR open — e.g.
   [`roles/implementor.md`](../roles/implementor.md) order
   (checklist → `ci.local_command` → lenses /
   [`policy/documentation-lenses.md`](documentation-lenses.md)
   **Pre-PR gate**), and the owning
   [`workflows/<workflow>.md`](../workflows/) sequence.
3. **Role contract sync.** Align each `roles/<role>.md` `## Inputs` and
   `## Output` with what the dispatching
   [`workflows/<workflow>.md`](../workflows/) passes and expects; keep
   `Used by:` in sync with those workflows (the shipped
   `role-workflow-symmetry` check covers the link list, not the contract
   text).
4. **Client capability check.** When the change requires subagents, consult
   `supports.subagents` in
   [`clients/compatibility.yaml`](../clients/compatibility.yaml); use the
   fresh-session fallback in
   [`policy/review-policy.md`](review-policy.md) and
   [`policy/documentation-lenses.md`](documentation-lenses.md).
5. **Provenance.** Attach a `**Source:**` line to every ported claim per
   [`policy/engineering-principles.md`](engineering-principles.md)
   §Provenance.
6. **Prompt-engineer lens.** After `ci.local_command` and before opening a
   PR — not as part of implementor step 4 pre-CI checklist work. Defer to
   [`roles/implementor.md`](../roles/implementor.md) step 6 and
   [`policy/documentation-lenses.md`](documentation-lenses.md)
   **Pre-PR gate** / `prompt-engineer`.

## Deprecation

Removing an observable harness behavior (schema field, enum value, script
CLI flag, generated-adapter path, or workflow obligation) is a breaking
removal and needs an explicit coexistence window and a machine-readable
marker, not a changelog line — see
[`policy/deprecation.md`](deprecation.md) for the classes, the minimum
window, and where the marker lives.

## Rollback

Products pin harness versions so rollback means repinning and regenerating
adapters, not editing generated files in place.
