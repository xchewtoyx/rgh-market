Stopping one task, saving its state, and starting another costs capacity
in its own right — a refocusing tax paid on top of whatever the two tasks
individually demand. This cost is not fixed across people; it can be
substantially amplified, making frequent switching disproportionately
expensive relative to the same total task list done in fewer, larger
blocks.

A distinct component of switching cost is **task-set change**: adopting an
instruction that overrides habitual responses (e.g., "count every letter f
on this page") and then abandoning that set for a new one ("now count
commas on the next page"). The second instruction is harder precisely
because the just-acquired tendency must be inhibited — executive control
must program working memory to follow a new rule. Under time pressure this
cost compounds: Add-3 is demanding partly because several digits must
simultaneously occupy different processing states (queued, transforming,
ready to report), which is itself a form of rapid internal switching.
Psychologists call adopting and terminating these sets "executive control";
it draws on the same [limited attention budget](limited-attention-budget.md)
as the task's substantive content.

The practical lever this implies is distinct from reducing how much work
there is: grouping similar tasks into one session (batching) reduces the
number of times the switching tax gets paid, without changing the
underlying task list at all. This is a different mechanism from [scheduled
batching of recurring demand](scheduled-batching-of-recurring-demand.md) —
that pattern bounds total exposure to one recurring demand inside a fixed
window; this one minimizes the marginal cost paid when *moving between*
different demands. A capacity budget that counts only task effort and
ignores switching frequency will systematically underestimate the cost of
a fragmented schedule relative to a batched one covering the same tasks.

For work that depends on a warmed-up, absorbed state (see [challenge-skill
balance](challenge-skill-balance.md)), an interruption's cost is
disproportionate to a normal switch: it doesn't just cost the refocus
time, it can collapse the state itself, so resuming means re-climbing into
that state from scratch rather than picking back up where the interruption
happened.

This cost is easy to underestimate at scale: reported figures put the
average knowledge worker at 50-60 interruptions a day, most of them not
actually important, with message-checking habits alone (e.g. every few
minutes under "immediate response" pressure) precluding any stretch long
enough to reach the switching-cost-amortizing benefit of a batched block
in the first place.
