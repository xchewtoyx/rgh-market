title: Task Batching
description: >
  Group similar tasks together into a single session rather than
  interleaving different task types, since each switch between task types
  costs disproportionate refocusing time.

Even a brief switch between unrelated tasks costs several minutes of
refocusing, on top of whatever time the interruption itself took — a cost
that's easy to underestimate because it's paid in small, diffuse
increments rather than one visible chunk. Deliberately batching similar
tasks into the same session (all emails together, all a given kind of
review together) avoids paying that refocusing cost repeatedly throughout
the day. This is a scheduling-level control, decided when the day or week
is planned, rather than something to manage task-by-task as it comes up.

The underlying assumption worth checking is the default itself: many
environments assume multitasking is the normal, expected mode of work.
Explicitly permitting single-tasking — doing one thing at a time by
design, not as a workaround — removes the pressure to interleave in the
first place, which is a precondition for batching to actually work in
practice.

Time-blocking pairs batching with [protected uninterrupted
time](protected-uninterrupted-time.md): reserve a morning chunk for admin
quick ticks and an afternoon chunk for deep work instead of fragmenting both
across the day. Monotasking within each block — one thing at a time — is
the execution mode that makes the batch worthwhile.
