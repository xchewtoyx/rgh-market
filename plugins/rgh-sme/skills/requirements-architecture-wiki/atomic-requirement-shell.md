The atomic requirement shell (Volere calls the physical card version a
"Snow Card") is the fixed container every discovered requirement gets
written into: a requirement number and type; the [business use case](business-event-and-use-case.md)
or event it belongs to; a plain description; its
[rationale](requirement-rationale.md); its originator; a
[fit criterion](fit-criterion.md); customer satisfaction/dissatisfaction
ratings (see [requirements prioritization](requirements-prioritization.md));
a priority; any known conflicts with other requirements; supporting
material; and a history of when it was created or changed.

The value of a fixed shell, rather than free-form requirements prose, is
that it makes every requirement's completeness mechanically checkable —
the [quality gateway](quality-gateway.md)'s completeness test is
essentially "are all the mandatory shell fields filled in?" — and it keeps
requirements as small, independently addressable units that can be
individually prioritized, traced, and revised, rather than as paragraphs
buried in a larger narrative document. Collected together, atomic
requirement shells are organized into the [Volere specification
template](volere-specification-template.md).
