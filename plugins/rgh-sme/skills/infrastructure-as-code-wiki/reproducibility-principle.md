---
type: concept
title: Reproducibility Principle
description: The Cloud Age design principle that every part of a system should be rebuildable effortlessly and reliably, with no judgment calls required at rebuild time.
sources:
  - title: Infrastructure as Code
    resource: "Infrastructure as Code (Kief Morris), ch. 2"
---

Making everything reproducible means you can rebuild any part of a system with a simple "yes/no" decision, with no need to make judgment calls about how to build it — configuration settings, software versions, and dependencies are all defined as code rather than assembled from memory or convention.

Reproducibility is what makes a failed system recoverable, but it also enables a broader set of capabilities: keeping test environments consistent with production, replicating a system across regions for availability, adding instances on demand under load, and giving each customer a dedicated, identically-built instance. It removes the risk and fear associated with making changes, because a mistake can simply be rebuilt away rather than diagnosed and repaired in place.

Data, content, and logs generated by a running system are the one thing you can't define ahead of time as code; a reproducibility strategy needs an explicit plan for carrying this state across a rebuild — see [data continuity strategies](data-continuity-strategies.md).

Reproducibility depends on [minimizing variation](minimize-variation-principle.md) across instances (an easily reproducible thing has few distinct types), and its absence produces [snowflake systems](snowflake-system.md). It is the foundation for [immutable infrastructure](immutable-server-pattern.md) and for [continuous disaster recovery](continuous-disaster-recovery.md), both of which depend on being able to recreate infrastructure on demand rather than nursing a single long-lived instance.
