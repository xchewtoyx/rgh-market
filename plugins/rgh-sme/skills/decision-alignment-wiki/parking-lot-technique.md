---
type: concept
title: Parking Lot Technique
description: >
  Visibly defer legitimate but off-topic points raised in a session
  to a tracked list instead of dropping them or letting them derail
  the agenda.
sources:
  - title: "Deciphering Data Architectures"
    resource: "Deciphering Data Architectures (James Serra), ch. 3"
---

A working session inevitably surfaces points that are real and worth
addressing but not the topic currently in front of the room. The
parking lot technique handles these without two common failure
modes: dropping the point entirely (it feels dismissed, and the
person who raised it disengages), or chasing it immediately (the
session loses its thread and never returns to the main agenda).

Mechanism: write the point down on a visible, shared record — the
same artifact the session is already using to track goals and
progress — the moment it comes up, then explicitly move the
discussion back on track. The point stays visible to everyone in the
room for the rest of the session, which signals it was heard and
will be addressed, not silently discarded. By the end of the
session, review the list and assign it the same treatment as any
other agreed follow-up: an owner and a next step
([decision-session-follow-up-package](decision-session-follow-up-package.md)),
not a line that quietly disappears once the room empties.

This is a companion to [managing-alignment-meetings](managing-alignment-meetings.md)'s
"prevent escape tactics" — but distinct from it. An escape tactic
(losing the group in low-level data, blaming absent people, debating
the facilitator's competence) is avoidance behavior to be named and
redirected. A parking-lot item is a genuine, legitimate point that
simply doesn't belong in the current conversation; it earns a place
on the record rather than a redirect.
