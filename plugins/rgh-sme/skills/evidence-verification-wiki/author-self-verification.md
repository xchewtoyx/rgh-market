# Author Self-Verification

Verifying one's own work is notoriously difficult because the human brain naturally reads what it *intended* to write rather than what is actually on the page. To perform effective **author self-verification**, an author must employ specific strategies to disrupt their familiarity with the text and force a critical, objective review.

## Self-Verification Strategies
- **The Cooling-Off Period**: Step away from the document for a period ranging from a few hours to several days before beginning verification. This allows the author's immediate memory of drafting to fade, making errors more visible.
- **Change Visual Context**: Alter the document's appearance to make it look unfamiliar to the brain. This can be achieved by:
  - Changing the font family, size, or color.
  - Printing the document on paper and reading it in a different physical location.
  - Converting the file to a different format (e.g., PDF or HTML layout).
- **Reverse Reading**: Read the document backward, sentence by sentence, starting from the very last sentence. This completely breaks the narrative flow, preventing the brain from getting absorbed in the story and skimming over factual errors.
- **Underline and Number Claims**: Walk through the text and underline every [checkable claim](defining-checkable-claims.md). Number each claim and map it to a specific row in a verification spreadsheet, listing the exact primary source and verification status.
- **Role-Play a Hostile Reader**: Read the text from the perspective of a highly critical stakeholder, competitor, or internet commenter who is actively looking for flaws, inaccuracies, or weak arguments.
- **Read from the Source's Perspective**: Read the text through the eyes of the person or entity being cited. This helps catch mischaracterizations, misquotes, and context-stripping errors.
