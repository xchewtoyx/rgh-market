---
type: concept
title: A Name Should Create a Clear Mental Image
description: >
  A good name conveys both what the underlying entity is and what it is
  not, which makes naming a form of abstraction — the same skill as
  abstraction elsewhere in design, applied to a single word or phrase.
sources:
  - title: A Philosophy of Software Design
    resource: "A Philosophy of Software Design (Ousterhout), ch. 14"
---

Self-test: if someone sees this name in isolation, without its declaration,
documentation, or usage context, how closely could they guess what it refers
to? Names become unwieldy past two or three words, so the real skill is
picking the few words that capture what matters most — exactly the same
challenge as [abstraction](abstraction.md) generally: a simplified way to
think about something more complex, where the best names highlight what's
important and omit the rest. This is why
[naming is a form of documentation](naming-as-documentation.md): a name that
creates the wrong mental image is worse than no name at all, because it
actively misleads instead of simply failing to inform.
